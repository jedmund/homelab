# Komodo

[stacks.toml](stacks.toml) declares the repository's Komodo stacks, review-app
Action, and associated user-group permissions.

## Ownership

Ansible writes Compose, environment, and configuration files on the hosts.
Komodo's static Stack resources use `files_on_host = true` and point to those
files. Update configuration through Ansible before redeploying in Komodo.

Static stacks disable `poll_for_updates` and `auto_update`. Application CI can
still request a redeployment after publishing an image. Keep the resource
name expected by that application's CI variables; it may differ from the
Ansible role name.

The `kizuna-storybook-review` Action creates temporary review stacks. Those
stacks are generated by the Action rather than by an Ansible product role.

## Resource Sync

Create a Resource Sync for this repository with:

```toml
resource_path = ["komodo/stacks.toml"]
```

Enable **Include Resources** and **Include User Groups**. The user-group
setting is required to apply the review Action's permission declarations.
Use the `homelab` match tag to scope the sync to these resources. Review the
resource and permission diff before applying it.

The declarations expect these Komodo Server resource names:

| Inventory host | Komodo Server |
| --- | --- |
| `nuc-mini` | `Atelier` |
| `max` | `max` |

Deploy the Ansible stack before adding its Komodo resource so the referenced
host files exist.

## Paths and lifecycle exceptions

Use the `run_directory` and `file_paths` in `stacks.toml` as the path reference.

| Stack | Exception |
| --- | --- |
| `line` | Builds from Ansible's checkout under `/opt/docker/line/source/line`; `auto_pull = false`, `run_build = true` |
| `kibble` | Retains `/opt/docker/feederhub` for existing data |
| `musicbrainz` | Uses `/opt/docker/musicbrainz/upstream` and `local/compose.merged.yml` |
| `beszel-agent-nuc-mini`, `beszel-agent-max` | Use `/opt/docker/beszel-agent` on different servers; the macOS agent is native and has no Stack resource |
| `vllm`, `sglang` | Model startup requires an explicit Compose profile; Resource Sync does not select a model |

## Periphery registry access

The Kizuna role writes its registry login to
`/etc/komodo/docker/config.json`. The `infra_core` role points Periphery's
`DOCKER_CONFIG` at that directory through its writable `/etc/komodo` mount.
The Docker CLI needs to create its `buildx` directory there. A read-only
credential-directory mount prevents that operation.

Periphery joins both the backend and shared networks. The backend network is
internal; the shared network supplies egress for registry update checks.
These settings are defined in
[infra_core's Compose template](../roles/infra_core/templates/compose.yaml.j2).
The standalone agent on `max` is documented in
[infra_periphery](../roles/infra_periphery/README.md).

## Kizuna Storybook review apps

The Action accepts the merge-request operation, IID, image, host, and revision
from `kizuna-app` CI. Its configuration restricts deployments to:

| Setting | Value |
| --- | --- |
| Server | `Atelier` |
| Image repository | `registry.atelier.house/kizuna/kizuna-app/storybook` |
| Host pattern | `storybook-mr-<iid>.review.atelier.house` |
| Network | `proxy-network` |
| Authentication | `tinyauth@file`, backed by PocketID |
| TLS resolver | `letsencrypt` |

Before enabling review deployments:

1. Deploy the gateway services with `make deploy-infra-gateway`. The ddclient
   role provisions the `*.review.atelier.house` DNS record; Traefik requests
   the review-domain wildcard certificate. Verify both are available.
2. Deploy `kizuna` and `infra_core` so Periphery has registry credentials and
   the required writable configuration path.
3. Create the Komodo service user `kizuna-storybook-review-ci`. Apply the
   Resource Sync, including user groups, and verify the user has execute-only
   access to `kizuna-storybook-review`.
4. In the application's CI variables, set `STORYBOOK_REVIEW_DOMAIN` to
   `review.atelier.house` and `KOMODO_STORYBOOK_REVIEW_ACTION` to
   `kizuna-storybook-review`. Set dedicated, masked, unprotected
   `KOMODO_STORYBOOK_API_KEY` and `KOMODO_STORYBOOK_API_SECRET` values for review
   jobs. Keep production deployment credentials separate.
5. Set `STORYBOOK_REVIEW_ENABLED=true` after DNS, TLS, permissions, and image
   pulls have been verified.

The resource name is `kizuna-storybook-mr-<iid>`. GitLab CI supplies deployment
and stop events. The stop operation removes the review containers and Stack
resource. Review containers have no published host port.

## Retired resources

Old thematic resources such as `media-acquisition`, `media-consumption`,
`content-management`, `reading`, `productivity`, `utilities`, and `development`
are not the current stack layout. If any remain in Komodo, confirm that their
replacement resources are in use before removing the resource entries.
Removing obsolete resources does not require deleting application volumes or
host data. Historical data migrations are recorded in
[retired migrations](../docs/retired-migrations.md).
